# AI Cyber Defense & Evolution System

An autonomous, self-improving cybersecurity system where AI agents continuously attack, defend, patch, and validate an application in a closed feedback loop. The system actively hunts for vulnerabilities in its own software, learns new firewall detection patterns on the fly, and uses large language models to generate and test code-level remediation patches—all while enforcing a strict **human-in-the-loop approval gate** before any patch touches production.

---

## The Evolution Loop

The core architecture operates as an autonomous, self-healing lifecycle:

```text
 ┌────────────────────────────────────────────────────────┐
 │                                                        │
 │   [ATTACK] ──► [DETECT] ──► [ANALYZE] ──► [FIX]        │
 │      ▲                                      │          │
 │      │                                      ▼          │
 │   [STRONGER] ◄── [LEARN] ◄── [TEST] ◄───────┘          │
 │    DEFENSE                                             │
 └────────────────────────────────────────────────────────┘
```

1. **ATTACK**: Red AI probes the application with targeted exploit payloads.
2. **DETECT**: Guardian AI intercepts incoming traffic, inspecting payloads against known pattern rules.
3. **ANALYZE**: Unblocked exploits pass through to the target app, logging successful breaches in real time.
4. **FIX**: Forge AI examines the vulnerable source code and attack logs to draft a hardened rewrite (`app_patched.py`).
5. **TEST**: Sentinel AI spins up the patched app on an isolated port, verifying that all attack payloads are neutralized and that all unit/regression tests still pass.
6. **LEARN**: Guardian AI's learning engine derives new WAF regex rules to block the exploit vector immediately at the network edge.
7. **STRONGER DEFENSE**: With the perimeter updated and a verified code patch ready for human review, the defense surface evolves to withstand the next attack wave.

---

## The 5 AI Agents

| Agent | Role | Description |
|---|---|---|
| **Red AI** | Attacker | Autonomous adversarial agent powered by Claude (default: `claude-sonnet-4-6`, with built-in fallback) that generates varied exploit payloads targeting SQL Injection, XSS, and Path Traversal. |
| **Guardian AI** | Defensive Proxy / WAF | High-performance reverse proxy sitting on port `8080`. Inspects all incoming traffic against dynamic rules (`rules.json`) and includes an AI learning pipeline (`learn_rule.py`) to synthesize new defense rules instantly. |
| **Forge AI** | Code-Patching Agent | Secure code remediation engine. Isolates vulnerable functions in source code and leverages Claude to write drop-in, parameterized security fixes while preserving business logic and comments. |
| **Sentinel AI** | Patch Tester & Validator | Automated quality & security gate. Runs a two-phase check on proposed patches: replays historical breach payloads to confirm mitigation, and runs the `pytest` regression suite to guarantee zero broken functionality. |
| **Memory AI** | Security Knowledge Base | *(Stage 6 — Upcoming)* Persistent vector and relational memory tracking past attack chains, defense effectiveness, and vulnerability trends over time. |

---

## What Makes This System Different

- **Closed-Loop Self-Healing**: Instead of merely alerting human analysts to a breach, the platform immediately generates edge firewall rules to stop ongoing attacks, creates source-level code patches, and validates them automatically.
- **Strict Human-Approval Gate**: AI proposes and validates fixes, but **never blindly deploys to production**. Patches remain staged in `target-app/app_patched.py` until a human engineer inspects the diff and authorizes the PR.
- **Dual-Layer Defense**: Combines immediate network-level mitigations (WAF rules in Guardian AI) with permanent code-level remediation (Forge AI + Sentinel AI).

## Setup Instructions

### 1. Prerequisites
- Python 3.10+
- `pip` package manager

### 2. Environment Configuration
Create a `.env` file in the project root:

```bash
# Anthropic Claude API (Used across Red AI, Guardian AI, and Forge AI)
ANTHROPIC_API_KEY="your-anthropic-api-key"
ANTHROPIC_WORKSPACE_ID="wrkspc_your_workspace_id"   # Required if using an unscoped user key
```

### 3. Dependency Installation
Install dependencies across all modules:

```bash
# Target App
pip install -r target-app/requirements.txt

# Red AI
pip install -r red-ai/requirements.txt

# Guardian AI
pip install -r guardian-ai/requirements.txt

# Forge AI
pip install -r forge-ai/requirements.txt

# Sentinel AI
pip install -r sentinel-ai/requirements.txt
```

## Running the Full Demo

To experience the evolution cycle end-to-end, run each component in separate terminals:

### Step 1: Start the Target Application
Launch the target app on port `5001`:
```bash
python3 target-app/app.py
```
*Health check:* Visit `http://127.0.0.1:5001` in your browser.

### Step 2: Start the Guardian AI Firewall Proxy
In a second terminal, start the defensive reverse proxy on port `8080`:
```bash
python3 guardian-ai/guardian.py
```
*All incoming traffic sent to port `8080` is now inspected and proxied to `5001`.*

### Step 3: Launch Red AI (Attacker)
In a third terminal, launch the exploit suite through Guardian AI:
```bash
python3 red-ai/red_ai.py --vuln sql_injection --target http://127.0.0.1:8080
```
- Red AI prints a visible banner stating whether it is using **Claude-generated payloads** (`claude-sonnet-4-6`) or the **built-in fallback** list.
- Previously known signatures are blocked (`403 Forbidden`).
- Any novel bypass vectors succeed and get logged into `red-ai/attack_log.json`.

### Step 4: Teach Guardian AI the New Exploit Signature
Run the learning pipeline with the payload that bypassed the firewall:
```bash
python3 guardian-ai/learn_rule.py --payload "' OR ''='"
```
*Guardian synthesizes a new regex pattern and hot-reloads `rules.json` without downtime. Re-running Step 3 will now show this vector blocked.*

### Step 5: Generate a Permanent Code Patch with Forge AI
Run Forge AI to analyze the attack logs and draft a secure code patch:
```bash
python3 forge-ai/forge_ai.py
```
*Forge AI generates `target-app/app_patched.py` with parameterized queries and creates a diff report in `forge-ai/patches/`.*

### Step 6: Validate the Patch with Sentinel AI
Run the automated security and regression suite:
```bash
python3 sentinel-ai/sentinel_ai.py --patched target-app/app_patched.py --port 5002
```
*Sentinel spins up the candidate on port `5002`, replays all 20+ attacks to verify they are blocked, runs all 5 `pytest` test cases, and outputs the final PASS/FAIL verdict for human review.*
